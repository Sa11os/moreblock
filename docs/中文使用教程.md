# MoreBlock 中文完整使用教程

这份文档把 MoreBlock 当前的两条主要内容链合在一起：

- 更多方块导入
- 更多实体导入

它适合资源作者、整合包作者、服主，以及需要排查导入问题的人直接查阅。

## 1. 模组能做什么

MoreBlock 会在游戏运行时读取：

- `config/moreblock/block`
- `config/moreblock/entity`

然后自动把其中的模型、贴图、动画、显示参数、交互配置注册成可用内容。

你可以把它理解成：

- 方块导入系统
- 实体导入系统
- 运行时资源包生成器
- 联机导入内容校验器
- 一部分可复用的动态注册 API

## 2. 环境要求

- Minecraft `1.20.1`
- Forge `47.x`
- GeckoLib `4.4.2+`
- Java `17`

联机时客户端和服务端都必须安装 MoreBlock，而且导入方块包、导入实体包也必须保持一致。

## 3. 首次启动会生成什么

第一次启动游戏后，MoreBlock 会自动创建：

```text
config/moreblock/block
config/moreblock/entity
```

同时生成：

```text
config/moreblock/block/.keep
config/moreblock/block/README.txt
config/moreblock/block/example/example.json
config/moreblock/block/example/example.md
config/moreblock/entity/.keep
config/moreblock/entity/README.txt
config/moreblock/entity/example/example.json
config/moreblock/entity/example/example.md
```

## 4. Blockbench 和资源准备

### 4.1 需要哪些工具

- `Blockbench`
- `GeckoLib Models & Animations` 插件
- `tools/blockbench/moreblock_blockbench_tools.js`
- PNG 贴图工具
- UTF-8 文本编辑器
- zip 压缩工具

### 4.2 模型格式要求

MoreBlock 最终读取的是 `GeckoLib` 导出的 `*.geo.json`。

如果你的原始 Blockbench 项目不是 GeckoLib 项目，通常需要：

1. 安装 `GeckoLib Models & Animations`
2. 转换项目为 `GeckoLib Animated Model`
3. 导出 `geo.json`
4. 如果是实体，还需要导出 `animation.json`

### 4.3 文件编码建议

- 所有 JSON 文件统一保存为 `UTF-8` 且无 BOM
- 文件名尽量使用小写英文、数字、下划线
- zip 文件名推荐使用 `UTF-8`

## 5. 更多方块导入

### 5.1 最少需要什么

最基础的导入方块至少要有：

- 一个 `*.geo.json`
- 一张 `*.png`

推荐再准备：

- 一个配置 `*.json`
- 一个 `*-display.json`

### 5.2 推荐目录结构

```text
blue_chair/
├─ blue_chair.json
├─ blue_chair.geo.json
├─ texture.png
└─ blue_chair-display.json
```

### 5.3 推荐配置写法

```json
{
  "id": "blue_chair",
  "name": {
    "zh_cn": "蓝色椅子",
    "en_us": "Blue Chair"
  },
  "geo": "blue_chair.geo.json",
  "texture": "texture.png",
  "display": "blue_chair-display.json",
  "light_level": 0,
  "supports_sitting": true,
  "seat_height": 0.45,
  "supports_lying": false,
  "lying_height": 0.5,
  "lying_rotation_compensation": 0
}
```

### 5.4 方块配置常用字段

- `id`
- `name.zh_cn`
- `name.en_us`
- `geo`
- `texture`
- `display`
- `light_level`
- `supports_sitting`
- `seat_height`
- `supports_lying`
- `lying_height`
- `lying_rotation_compensation`

### 5.5 方块交互规则

- `supports_sitting` 和 `supports_lying` 互斥
- 两个都开时，两者都不会生效
- 白天躺下不会跳时间，只是进入白天躺下状态

### 5.6 方块 zip 兼容

支持：

- 直接放文件夹
- 直接放 `zip`
- `zip` 里套一层同名文件夹
- 外层 `zip` 里混合多个文件夹和子 `zip`

## 6. 更多实体导入

### 6.1 最少需要什么

最基础的导入实体至少要有：

- 一个 `*.geo.json`
- 一张 `*.png`

推荐再准备：

- 一个 `*.animation.json`
- 一个配置 `*.json`

### 6.2 推荐目录结构

```text
blue_slime/
├─ blue_slime.json
├─ blue_slime.geo.json
├─ blue_slime.animation.json
└─ texture.png
```

### 6.3 推荐配置写法

```json
{
  "id": "blue_slime",
  "name": {
    "zh_cn": "蓝色史莱姆",
    "en_us": "Blue Slime"
  },
  "geo": "blue_slime.geo.json",
  "texture": "texture.png",
  "animation": "blue_slime.animation.json",
  "width": 0.9,
  "height": 0.9,
  "eye_height": 0.65,
  "max_health": 30.0,
  "movement_speed": 0.28,
  "follow_range": 24.0,
  "attack_damage": 4.0,
  "armor": 2.0,
  "knockback_resistance": 0.1,
  "tracking_range": 8,
  "update_interval": 3,
  "ai_enabled": true,
  "ai_template": "minecraft:zombie",
  "animation_transition": true,
  "animation_states": {
    "idle": {
      "idle": 1.0,
      "idle_1": 0.6,
      "idle_2": 0.4
    },
    "walk": {
      "walk": 1.0,
      "walk_1": 0.5
    },
    "run": {
      "run": 1.0
    },
    "attack": {
      "attack": 1.0,
      "attack_1": 0.8
    },
    "hurt": {
      "hurt": 1.0
    },
    "spawn": {
      "spawn": 1.0
    },
    "die": {
      "die": 1.0,
      "die_1": 0.6,
      "die_2": 0.4
    }

  "spawn_egg_primary_color": "#4b7cf0",
  "spawn_egg_secondary_color": "#d8e4ff",
  "show_in_moreblock_tab": true,
  "translucent": true
}
```

- `geo`
- `texture`
- `animation`

- `max_health`
- `movement_speed`
- `follow_range`

### 6.5 实体动画状态命名

支持这些基础状态：

- `spawn`
- `idle`
- `walk`
- `run`
- `attack`
- `hurt`
- `die`

同一状态可以写多个动作，例如：

- `idle_1`
- `idle_2`
- `attack_1`
- `die_2`

### 6.6 实体 AI 模板

当前已适配一批基础原版模板，例如：

- `minecraft:cow`
- `minecraft:pig`
- `minecraft:sheep`
- `minecraft:chicken`
- `minecraft:mooshroom`
- `minecraft:zombie`
- `minecraft:husk`
- `minecraft:spider`
- `minecraft:cave_spider`
- `minecraft:skeleton`
- `minecraft:stray`

### 6.7 实体 zip 兼容

支持：

- 直接放实体包文件夹
- 直接放 `zip`
- `zip` 里套一层同名文件夹
- 外层 `zip` 里混合多个文件夹或子 `zip`

## 7. Blockbench 工具脚本能做什么

仓库自带脚本：

```text
tools/blockbench/moreblock_blockbench_tools.js
```

现在可以：

- 导出 MoreBlock 方块配置 JSON
- 导出 MoreBlock 实体配置 JSON
- 生成 MoreBlock `hitbox` 骨骼

## 8. 导入后会注册什么

### 8.1 方块导入成功后

会自动生成：

- 方块
- 对应物品
- 运行时资源包内容
- 语言文件内容
- 方块状态与空模型文件

### 8.2 实体导入成功后

会自动生成：

- 实体类型
- 刷怪蛋
- 运行时资源包内容
- 语言文件内容
- 实体模型、贴图、动画挂载

## 9. 联机与同步说明

MoreBlock 现在会同时校验：

- 导入方块包
- 导入实体包

### 9.1 方块包指纹内容

- 注册名
- 显示名
- 配置文件
- 模型文件
- 显示文件
- 贴图文件

### 9.2 实体包指纹内容

- 注册名
- 显示名
- 配置文件
- 模型文件
- 动画文件
- 贴图文件

### 9.3 不一致时会怎样

如果客户端缺包、多包，或者内容不同：

- 登录时会被拦截
- 或进服后校验失败被断开

这是正常保护机制。

## 10. 游戏内命令

- `/moreblock block list`
- `/moreblock block check`
- `/moreblock entity list`
- `/moreblock entity check`

这些命令主要用于：

- 确认有没有被识别
- 看当前读到了多少个导入内容
- 检查主手方块或刷怪蛋来自哪个文件夹或 zip

## 11. 推荐测试流程

### 11.1 方块

1. 把方块包放进 `config/moreblock/block`
2. 重启客户端或服务器
3. 用创造栏或 `/moreblock block list` 检查
4. 用 `/moreblock block check` 查来源

### 11.2 实体

1. 把实体包放进 `config/moreblock/entity`
2. 重启客户端或服务器
3. 找刷怪蛋或用 `/moreblock entity list` 检查
4. 用 `/moreblock entity check` 查来源

## 12. 常见问题

### 12.1 内容没加载出来

优先检查：

- 文件有没有放对目录
- 模型是不是 GeckoLib `*.geo.json`
- 贴图是不是可用 `png`
- 配置里的文件名有没有写错
- JSON 是否为 `UTF-8` 且无 BOM

### 12.2 进服被踢

优先检查：

- 客户端和服务端是否安装相同版本 MoreBlock
- 客户端和服务端的导入包是否完全一致
- 是否有人改动过 JSON、贴图、geo、display 或 animation

### 12.3 动画不对

优先检查：

- `animation` 文件名是否写对
- 动画状态命名是否符合约定
- 是否错误开启或关闭了 `animation_transition`
- 是否需要关闭 `disable_vanilla_death_animation`

## 13. 给内容作者的建议

如果准备长期维护几十个甚至上百个内容，建议统一：

- 每个内容单独一个文件夹
- 每个内容都写配置文件
- `texture.png` 统一命名
- geo、json、display、animation 文件与内容 ID 对齐命名
- 发布前统一打 zip
- 客户端和服务端始终用同一份导入包
