# MoreBlock 实体导入说明

这份说明面向想把 GeckoLib 实体模型直接放进 `config` 目录里使用的人。

当前这版已经提供一个稳定的基础闭环：

- 从 `config/moreblock/entity` 扫描实体包
- 同时支持文件夹和 `zip`
- 自动生成运行时资源包
- 自动注册实体类型和刷怪蛋
- 自动生成示例配置与参数说明文件
- 自动进行客户端与服务端的实体包内容校验

## 1. 首次启动后会生成什么

第一次启动游戏后，模组会自动创建：

```text
config/moreblock/entity
config/moreblock/entity/.keep
config/moreblock/entity/README.txt
config/moreblock/entity/example/example.json
config/moreblock/entity/example/example.md
```

其中：

- `README.txt` 是目录说明
- `example.json` 是可直接复制的模板
- `example.md` 是每个字段的解释
- `example` 文件夹只作参考，不会被实际导入

## 2. 一个最基础的实体包

推荐目录结构：

```text
blue_slime/
├─ blue_slime.json
├─ blue_slime.geo.json
├─ blue_slime.animation.json
└─ texture.png
```

最少需要：

- 一个 GeckoLib `*.geo.json`
- 一张 `png` 贴图

可选文件：

- `*.animation.json`
- 一个配置 `*.json`

如果你不写配置文件，只放模型和贴图，MoreBlock 也会尝试按目录名推导一份基础导入定义；但长期维护时还是建议每个实体都写配置。

## 3. 推荐配置写法

```json
{
  "id": "blue_slime",
  "name": {
    "zh_cn": "蓝色史莱姆",
    "en_us": "Blue Slime"
  },
  "geo": "blue_slime.geo.json",
  "texture": "texture.png",
  "animation": "blue_slime.animation.json",
  "width": 0.9,
  "height": 0.9,
  "eye_height": 0.65,
  "max_health": 30.0,
  "movement_speed": 0.28,
  "follow_range": 24.0,
  "attack_damage": 4.0,
  "armor": 2.0,
  "knockback_resistance": 0.1,
  "tracking_range": 8,
  "update_interval": 3,
  "ai_enabled": true,
  "ai_template": "minecraft:zombie",
  "animation_transition": true,
  "animation_states": {
    "idle": {
      "idle": 1.0,
      "idle_1": 0.6,
      "idle_2": 0.4
    },
    "walk": {
      "walk": 1.0,
      "walk_1": 0.5
    },
    "run": {
      "run": 1.0
    },
    "attack": {
      "attack": 1.0,
      "attack_1": 0.8
    },
    "hurt": {
      "hurt": 1.0
    },
    "spawn": {
      "spawn": 1.0
    },
    "die": {
      "die": 1.0,
      "die_1": 0.6,
      "die_2": 0.4
    }
  },
  "disable_vanilla_death_animation": true,
  "spawn_egg_primary_color": "#4b7cf0",
  "spawn_egg_secondary_color": "#d8e4ff",
  "show_in_moreblock_tab": true,
  "translucent": true
}
```

## 4. 字段说明

| 字段 | 是否推荐 | 说明 |
| --- | --- | --- |
| `id` | 推荐 | 实体短 ID，会参与注册名生成。 |
| `name.zh_cn` | 推荐 | 中文显示名。 |
| `name.en_us` | 推荐 | 英文显示名。 |
| `geo` | 推荐 | GeckoLib 实体模型文件名。 |
| `texture` | 推荐 | 贴图文件名。 |
| `animation` | 可选 | 动画文件名。不填时会使用内置默认 idle 动画。 |
| `width` | 可选 | 实体碰撞宽度。默认 `0.6`。 |
| `height` | 可选 | 实体碰撞高度。默认 `1.8`。 |
| `eye_height` | 可选 | 实体视线高度。默认按高度自动推导。 |
| `max_health` | 可选 | 最大生命值。默认 `20`。 |
| `movement_speed` | 可选 | 基础移动速度。默认 `0.2`。 |
| `follow_range` | 可选 | 目标跟随距离。默认 `16`。 |
| `attack_damage` | 可选 | 基础攻击伤害。默认 `2`。 |
| `armor` | 可选 | 基础护甲值。默认 `0`。 |
| `knockback_resistance` | 可选 | 击退抗性。默认 `0.2`。 |
| `tracking_range` | 可选 | 客户端追踪距离。默认 `8`。 |
| `update_interval` | 可选 | 实体同步更新间隔。默认 `3`。 |
| `ai_enabled` | 可选 | 是否启用 AI。默认 `true`。 |
| `ai_template` | 可选 | 原版生物 AI 模板 id，例如 `minecraft:zombie`。 |
| `animation_transition` | 可选 | 是否启用动作切换过渡。默认 `true`。 |
| `animation_states` | 可选 | 动画状态与权重配置，支持 `spawn`、`idle`、`walk`、`run`、`attack`、`hurt`、`die`。 |
| `disable_vanilla_death_animation` | 可选 | 是否禁用原版死亡翻转效果。有 `die` 动画时默认 `true`，没有时默认 `false`。 |
| `spawn_egg_primary_color` | 可选 | 刷怪蛋主色。 |
| `spawn_egg_secondary_color` | 可选 | 刷怪蛋副色。 |
| `show_in_moreblock_tab` | 可选 | 是否把自动生成的刷怪蛋显示在 MoreBlock 创造栏。默认 `true`。 |
| `translucent` | 可选 | 是否按半透明材质渲染。默认 `true`。 |

## 6. 动画状态与权重

当前基础状态命名约定如下：

- 出生：`spawn`
- 待机：`idle`
- 攻击：`attack`
- 行走：`walk`
- 跑动：`run`
- 受伤：`hurt`
- 死亡：`die`

如果动画文件中出现同一状态的多个动作，例如：

- `idle_1`
- `idle_2`
- `run_1`
- `attack_1`
- `hurt_1`
- `spawn_1`
- `die_2`

系统会自动按前缀识别为对应状态的动作池。

如果你还想手动控制随机播放权重，可以在配置里写：

```json
"animation_states": {
  "idle": {
    "idle": 1.0,
    "idle_1": 0.6,
    "idle_2": 0.4
  },
  "attack": {
    "attack": 1.0,
    "attack_1": 0.8
  },
  "walk": {
    "walk": 1.0,
    "walk_1": 0.5
  },
  "die": {
    "die": 1.0,
    "die_1": 0.6,
    "die_2": 0.4
  }
}
```

说明：

- 数值越大，被随机选中的概率越高
- 不写 `animation_states` 时，会自动按动画文件里的命名分组
- 某个状态没配时，会优先使用自动识别结果
- `run` 没找到动作时，会优先回退到 `walk`
- `spawn`、`attack`、`hurt`、`die` 没找到动作时，会回退到 `idle`

## 7. zip 载入规则

实体导入和方块导入保持一致，也支持：

- 直接放一个实体包文件夹
- 直接放一个 `zip`
- `zip` 里套一层同名文件夹
- 外层 `zip` 里混合多个文件夹或子 `zip`

## 8. Blockbench 制作与导出

### 8.1 模型格式要求

实体导入同样读取 `GeckoLib` 的 `*.geo.json` 和可选 `*.animation.json`，不是原版普通实体模型格式。

### 8.2 内置 Blockbench 工具脚本

仓库里已经提供了 MoreBlock 专用脚本：

```text
tools/blockbench/moreblock_blockbench_tools.js
```

它现在可以直接导出 MoreBlock 实体配置 JSON，支持填写：

- `id`
- 中英文名称
- `geo`
- `texture`
- `animation`
- 尺寸、属性、AI 模板
- 动画过渡、死亡翻转开关
- 刷怪蛋颜色
- 动画状态模板

## 9. 导入后怎么测试

基础版会自动给每个导入实体注册一个刷怪蛋。

当前 `ai_template` 已适配一批常见原版模板：

- `minecraft:cow`
- `minecraft:pig`
- `minecraft:sheep`
- `minecraft:chicken`
- `minecraft:mooshroom`
- `minecraft:zombie`
- `minecraft:husk`
- `minecraft:spider`
- `minecraft:cave_spider`
- `minecraft:skeleton`
- `minecraft:stray`

`minecraft:ender_dragon` 暂时不在这批基础模板里。末影龙不是普通 `Goal` 型生物，而是独立的 Phase 状态机 Boss；如果要做接近原版的行为和动画，建议先看 `docs/生物动画序列/末影龙-AI与动画序列建议.md`。

建议测试顺序：

1. 把实体包放进 `config/moreblock/entity`
2. 重启客户端或服务器
3. 打开 MoreBlock 创造模式页签找刷怪蛋
4. 或用命令 `/moreblock entity list` 看有没有被识别
5. 主手拿着刷怪蛋时用 `/moreblock entity check` 查看来源

## 10. 联机与同步说明

MoreBlock 现在也会校验客户端和服务端的导入实体包清单。

实体包内容指纹会综合以下内容：

- 注册名
- 显示名
- 配置文件内容
- 模型文件内容
- 动画文件内容
- 贴图文件内容

如果客户端缺包、多包，或包内容不同：

- 登录时会被拦截
- 或进服后校验失败被断开连接

这是正常保护机制，不是 bug。

## 11. 当前基础版的定位

这一版重点先把“导入、注册、渲染、刷怪蛋、联机校验、示例和文档”这条主链打通，方便你先把实体资源跑起来。

如果后面要继续扩，比较合适的方向包括：

- 更完整的动画控制
- AI、行为和交互配置
- 更细的分类与生成规则
- 更详细的实体调试命令
